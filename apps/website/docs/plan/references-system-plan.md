# References System Development Plan

## Overview

This plan outlines the development of the References system for RippleBase, focusing on creating a robust research management system that supports both manual entry and automatic enrichment of references.

## System Design Principles

### Canonical vs Secondary References

- **Canonical References**: Primary references entered by users or promoted secondary references
- **Secondary References**: URLs found within canonical references
- **Auto-promotion**: Secondary references with reference_count > 1 become canonical
- **Enrichment**: Only happens once per reference (checks for existing raw_content)

### Technical Decisions

1. **Keep canonical/secondary design** - It's solid and creates a self-organizing knowledge graph
2. **Use text[] for keywords** - Sufficient for our scale with GIN indexing
3. **Add enrichment_status field** - Better tracking than null checks
4. **Separate vector table** - Cleaner architecture for future semantic search
5. **Fix type system first** - Prevent cascading bugs

## Performance Optimizations

### Required Indexes

```sql
CREATE INDEX idx_reference_keywords ON reference USING GIN (keywords);
CREATE INDEX idx_reference_canonical ON reference (canonical) WHERE canonical = true;
CREATE INDEX idx_reference_brand ON reference (brand);
CREATE INDEX idx_reference_process ON reference (process) WHERE process = true;
CREATE INDEX idx_reference_url ON reference (url);
CREATE INDEX idx_reference_created ON reference (created_at DESC);
```

- Cache individual references for 10 minutes

## Phase 5: Collections System (Future Enhancement)

### 5.1 Database Schema for Collections

```sql
-- Reference Collections table
CREATE TABLE reference_collection (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  name TEXT NOT NULL,
  description TEXT NULL,
  brand BIGINT NOT NULL REFERENCES brand(id) ON DELETE CASCADE,
  created_by TEXT NULL, -- user_id
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW(),
  color TEXT NULL, -- for UI organization
  is_public BOOLEAN DEFAULT FALSE
);

-- Many-to-many relationship between references and collections
CREATE TABLE reference_collection_item (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  collection_id BIGINT NOT NULL REFERENCES reference_collection(id) ON DELETE CASCADE,
  reference_id BIGINT NOT NULL REFERENCES reference(id) ON DELETE CASCADE,
  added_at TIMESTAMPTZ DEFAULT NOW(),
  added_by TEXT NULL, -- user_id
  notes TEXT NULL, -- optional notes about why this reference is in this collection
  UNIQUE(collection_id, reference_id)
);

-- Indexes for performance
CREATE INDEX idx_reference_collection_brand ON reference_collection(brand);
CREATE INDEX idx_reference_collection_item_collection ON reference_collection_item(collection_id);
CREATE INDEX idx_reference_collection_item_reference ON reference_collection_item(reference_id);
```
